# Модель угроз

## Что защищаем

- IP-адрес пользователя от наблюдателя между устройством и сервером (WireGuard-туннель).
- DNS-запросы: уходят внутрь туннеля (DNS из конфига), при системном kill switch —
  блокируются при обрыве.
- Трафик от пассивного перехвата в сети (шифрование WireGuard, ChaCha20-Poly1305).
- Локальные секреты: приватные ключи в Keystore-шифрованном файле.

## От каких угроз защита работает

1. Перехват трафика в открытой Wi-Fi сети — да.
2. Подмена DNS провайдером — да, при активном туннеле.
3. Извлечение ключей из украденного файла данных приложения — да (Keystore),
   за исключением сценариев с root-доступом к разблокированному устройству.
4. Подмена обновлений — на этапе 4: подпись Ed25519, публичный ключ в приложении.

## От чего защита НЕ работает (ограничения)

- Вредонос с root-правами на самом устройстве.
- Сам VPN-сервер видит метаданные подключения (кто, когда, объём, назначение).
- Провайдер VPN-сервера (VPS) теоретически может снимать трафик на выходе.
- Корреляционные атаки «глобального наблюдателя» (тайминги вход/выход).
- Отключённый kill switch: обрыв туннеля без него означает, что часть трафика
  пойдёт напрямую.
- GoBackend — userspace-реализация: чуть ниже производительность, чем kernel-WG,
  зато не требует root.

## Что приложение НЕ делает

- Не пишет историю посещений, не инспектирует содержимое трафика.
- Не содержит аналитики/рекламы/трекеров.
- Не отправляет данные третьим сторонам (сейчас — вообще ничего; диагностика на
  этапе 4 — только opt-in и только коды ошибок).
